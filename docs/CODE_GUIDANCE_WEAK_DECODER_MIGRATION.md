# 代码指导：把 main_v0 的低 gap 经验迁移到"弱解码器 + 低维资源级 θ"主路线

> 适用：`Constrained_AwareMKP` 的 `main_v0@6a4cf82`（"当前代码"）。执行方：Codex。指导方：Claude。
> 旧项目：`RL_ModelInhance`（v6，`40_lp-dual-bipartite-bound-shaping@a933ff7`）。
> 研究边界以 `docs/RESEARCH_HANDOFF_FROM_OLD_PROJECT.md` 第 2 节为准，本指导不放宽任何条目。

## 0. 背景与目标

用户的诉求是把 main_v0 记录到的"gap < 0.1%"迁移到旧项目的研究思路上，也就是"学习控制器 → 低维资源级 θ → 无参数透明执行器"。核对源码和本地结果后，有三条事实决定了迁移该怎么做（证据等级 A，均可由本地 CSV 复算）：

| 来源 | Chu 180 实例（M∈{5,10}）平均 best-known gap | 是否满足弱解码器边界 |
|---|---|---|
| main_v0：静态 LP 价格比 greedy | 0.711% | 是（无学习） |
| main_v0：学习策略 greedy（含逐物品 δ_j） | 0.439% | **否**，违反 I-2 |
| main_v0：greedy + 256 次采样 | 0.244% | 否，属于多轨迹阶段 |
| main_v0：再加 ADD/SWAP/DROP-REFILL/ILS | **0.074%** | 否，属于搜索阶段 |
| 旧项目 v6：学习策略 greedy（θ 有 M+8+M(M+1)/2+K 个分量） | 0.310% | 是，但 θ 冗余 |
| main_v1@942877a：去掉 δ 后的 learned greedy（3 个种子） | 0.597–0.624% | 是 |
| main_v1：dual_root greedy | 0.745% | 是 |

这些数字支持以下结论：

1. **0.074% 主要来自多轨迹加搜索，不是来自低维接口。** 在单轨迹 greedy 上，main_v0 的 0.439% 还混着 δ_j 的作用。历史 per_instance 中 |δ| 的均值为 2.02（上限 3），说明 δ 被大量使用。
2. **去掉 δ 之后，单轨迹 greedy 会明显退化。** main_v1 的同类改造只到了 0.60%，比旧项目 v6 的 0.31% 差约 0.3 个百分点。
3. **旧项目 v6 中真正"活着"的 θ 分量很少。** 按 M=5 / M=10 分列：
   - 实际被使用的分量：
     - π（资源价格）
     - α（收益指数）：1.47 / 1.80
     - η（LP 原始解权重）：0.75 / 1.42
     - λ（机会/阻断权重）：0.24 / 0.34
   - 退化到接近 0 或接近边界的分量：
     - κ：0.010 / 0.003
     - δ_LP：0.017 / 0.006
     - A：约 0.03 / 0.001
     - ρ：0.022（M=5 时）
     - 搭配项 b 只影响约 2% 的分数幅度
     - τ 不改变 greedy 排序
4. **main_v0 自身的 θ 也已坍缩：** w_price_ratio 约 0.95，κ 约 86（κ 只是温度，不影响 greedy）。

**由此得到的迁移目标：** 在"单轨迹 greedy、无逐物品学习输出、无参数执行器"的边界内，用精简后的 θ 和少数几个透明的运筹基函数，逐步把 greedy gap 从约 0.6%（去掉 δ 后的起点）压向 0.31%，并继续向 0.1% 推进。0.1% 的 greedy 目标目前是研究假设（C 级）。多采样和搜索可以继续做出 ≤0.1% 的数字，但只能作为**单独命名的阶段**报告，并且固定 θ 臂要在同一预算下给出对照。

## 1. 硬性要求一：弱解码器研究边界

以下条目由 Codex 落实到代码和评测中，任何一条都不能悄悄放宽。

**B-1 主方法 = 单轨迹 greedy。** 主表的第一列只能是 `greedy`（1 条轨迹，argmax）。`sampleK` 和 `+LS/ILS` 是另外命名的阶段（P-4），并且各臂必须用相同的 K 和相同的搜索预算。
- 论文和报告中不能把 `gap_final` 称为"弱解码器的效果"。

**B-2 执行器没有可训练参数，也没有逐物品学习输出。**
- 删除 `StrategyController.res_head` 和 `residual_max`，以及 `WeakDecoder` 中 `+ strat["residual"]` 这一项。
- 执行器的输入只有两类：θ（维度与 N 无关），以及固定、透明的物品级基函数。
- 编码器内部可以有物品表示，但物品表示不能直接进入分数。

**B-3 执行器不做搜索。** 执行器里不能有 lookahead rollout、beam search、修复或 MILP 选取整数解。下面两样是允许的，前提是写清成本，并能单独消融：
- LP 松弛作为固定基函数或锚点；
- 一步阻断量作为透明基函数。

**B-4 训练期的多采样不算强解码。** 可以保留 main_v0 的 POMO 式同实例 K=16 采样基线，它是方差缩减手段。但推理期的主指标只能用 1 条轨迹。

**B-5 可行性由执行器保证。** 主方法改为在可行集合上做 softmax，对应 `hard_mask`，与旧项目 v6 一致。
- `perceive`（拒绝模式）降为单独命名的对照臂。
- 理由：greedy 下拒绝模式与 mask 在解上几乎等价，而低拒绝率又不能证明约束理解（L-12）。
- 主方法的奖励中去掉 `reject_penalty`。

**B-6 遗留的 δ_j 只做对照。** 如需保留，命名为 `legacy_delta` 臂，用于误差分析，不进入主方法名称和主表。

## 2. 硬性要求二：二部图数据结构是否继承——裁决：**继承"物品 token + 资源 token + 稠密关系值"的二部结构，不继承旧项目的重型附件**

**为什么继承：** 这套结构几乎直接对应 R-1～R-7 中的大部分需求。
- **R-2 / E-3：** θ 以资源为索引，价格要从资源 token 上逐个读出。这一点 main_v0 的 `price_head([y_i, ctx])` 已经实现，并且对资源排列等变。没有资源一等实体的结构，反而需要额外设计读出路径。
- **R-1：** 结构天然支持可变 N 和 M，并对物品和资源的排列保持不变或等变。
- **E-4：** MKP 的消耗矩阵是稠密的，信息在关系的数值上。main_v0 用 `EdgeBias` 把关系值注入注意力 bias，这与"矩阵元素作注意力 bias"的做法一致。
- **R-7：** main_v0 已经实现"静态编码一次 + 每步融合动态特征"，每步成本远低于旧项目的每步全图重编码（旧项目在 N=500 时单实例约 34 秒）。
- 这套代码已经存在且能跑出结果，换结构会同时改变多个因素，违反 L-5。

**不继承的部分（至少在 T1–T3 期间）：**
- 旧项目 encoder 中 7 维的物品–物品关系注意力（O(N²M)，每步重算）、机会查询、对比池化、独立 critic 编码器。
- 原因：互斥信息（R-4）改由**执行器中的透明阻断基函数**承担，见 §3 的 G2。这样"组合效应"进入的是可审查的评分项，而不是黑盒表示。表示侧是否还需要 O(N²) 关系，留到 T4 做 Q-5 消融。
- 不按 Gasse 式变量–约束图来叙述，论文中只称"物品–资源关系编码"。

**需要调整的地方，放到 T4 单独做：**
- 控制器中资源 token 汇聚的 key 和池化集合，从"未处理物品"改为"当前可行物品"（E-6，与 hard_mask 执行器的候选集一致）。
- 在 mean/max 池化之外，补一个对关键候选的注意力池化（R-5）。
- 两项都作为表示消融，不并入 T1。

## 3. 硬性要求三：θ 精简设计

**设计原则：**
- θ 的维度不超过 M+3，不允许出现 O(M²) 项。
- 每个分量都有一句话能说清的语义，并且有旧项目或 main_v0 的数据表明它确实被使用过。
- 能被其他分量吸收的分量一律删除。

**最终 θ_t：** 在每个构造步由当前残余状态重算（I-4），按组逐步启用（Q-4）。

| 组 | 分量 | 维度 | 参数化 | 语义 |
|---|---|---|---|---|
| G0 | u_t | M | `u = u_max·tanh(·)`，再减去均值（Σu=0，消除价格整体尺度这个冗余自由度） | 资源 j 的价格相对 LP 对偶锚点的对数修正：λ_tj = base_j·exp(u_tj) |
| G1 | α_t | 1 | `0.5 + 2·sigmoid(·)`，取值 [0.5, 2.5]，初值 1 | 收益指数，对应收益与资源成本之间的权衡 |
| G2 | γ_t | 1 | `softplus(·)`，初值约 0.1 | 对"阻断损失"的厌恶程度 |
| G3 | η_t | 1 | `softplus(·)`，初值约 0.5 | 对残余 LP 原始解的信任程度 |

**执行器分数**（没有可训练参数，只在可行集合 F(s) 上计算）：

```
s_i(θ) = α·log p̃_i − log Σ_j λ_tj · r_ij / (c_rem_j + 1)          # G0+G1：动态代理比（Senju–Toyoda 式余量归一）
         − γ · blocked_i                                           # G2：选 i 后不再能放入的其他可行物品的收益占比
         + η · log(x^LP_i + 0.01)                                  # G3：残余 LP 原始解（固定基函数）
π(i|s) = softmax_{i∈F(s)}( s_i / T )
```

各项说明：
- `p̃ = p / mean(p)`。
- `blocked_i = Σ_{k∈F, k≠i} p_k·1[∃j: r_kj > c_rem_j − r_ij] / Σ_{k∈F} p_k`。其计算量为 O(N²M)，需要分块计算。
- T 是**全局**温度，不属于 θ，二选一：一个与状态无关的可学习标量 `nn.Parameter`（推荐，初值 1/3），或一个常数。greedy 不受 T 影响。

**删除项及理由：**

| 删除项 | 理由 |
|---|---|
| main_v0 的 δ_j | 违反 I-2 |
| main_v0 的 κ_t | 是温度，不影响 greedy；学到约 86 也只说明训练需要更尖锐的采样，因此由全局 T 承担 |
| main_v0 的 4 基元混合 w_t，以及各基元的 z-score | price_ratio 已占约 95%；efficiency 是 u=0 时 price_ratio 的静态特例；slack 被 hard_mask 和 G2 覆盖；profit 由 α 表达。改为上面的对数域显式公式 |
| 旧项目的 β（稀缺指数） | 动态 u 可以吸收 β·log(c/c_rem) 的效果；余量归一固定为 Senju–Toyoda 形式 |
| 旧项目的 κ（瓶颈权重） | 学习值约 0.003–0.01，已坍缩 |
| 旧项目的 ρ（余量权重） | 与 G2 概念重叠，且 M=5 时约为 0 |
| 旧项目的 δ_LP（约化成本权重） | 约为 0；与 η 项单调相关（L-4） |
| 旧项目的 A（M(M+1)/2 资源对矩阵） | 约为 0；O(M²) |
| 旧项目的 b（搭配项） | 只影响约 2% 的分数幅度，需要 O(N²) 的伙伴计算 |
| 旧项目的 τ | 不影响 greedy，由全局 T 承担 |

**锚点 base_j 有两个选项**（对应 Q-2，由配置决定）：
- `root`：沿用 main_v0 的静态 `mu + price_floor·mean(mu)`；
- `residual`：每步用残余 LP 重算对偶 y_t。只有在 G3 已经要求每步做 LP 时，才顺带启用。

u≡0 时，模型本身就退化为"固定 LP 对偶价格"臂，因此 Q-2 自动成为模型自身的消融。

**控制器读出：**
- u 沿用 `price_head([y_j, ctx])`，逐资源读出。
- α、γ、η 由 `ctx` 经一个 `Linear(d, n_scalar)` 输出。
- 末层零初始化，偏置设为各分量的初值。这样 untrained=fixed 的问题需要用 §4 中的 untrained 定义另行处理。

## 4. 对照臂与评测口径（Q-1 / P-3 / P-4）

所有臂共用同一个执行器、同一组 θ 分量、同一个推理阶段和同一预算：

| 臂 | 定义 |
|---|---|
| `fixed` | u=0，α=1，γ、η 取初值，不经过网络 |
| `fixed_dualgreedy` | main_v0 原有的 `greedy_dual_ratio`，静态 c，作为历史参照 |
| `untrained` | 同一架构，heads 用 PyTorch 默认随机初始化（不做零初始化），与训练臂使用相同种子 |
| `learned_static` | **单独训练**，θ 只在 t=0 计算一次，之后整条轨迹冻结（配置项 `theta_update=static`）。不能用动态训练模型在推理时冻结来代替：main_v1 这样做的 learned_static 为 1.27–2.48%，比 fixed 还差，是分布外使用，不能作为证据 |
| `learned_dynamic` | 主方法 |
| `legacy_delta`（可选） | main_v0 原模型，仅作对照 |

**评测要求：**
- **阶段：** `greedy`（主）、`sample64` / `sample256`、`greedy+ILS`、`sampleK+ILS`。各阶段单独计时，LP 的计时边界要写清。
- **统计：** 逐实例配对；3 个独立训练种子；报告 Wilcoxon 检验和配对差（单位为百分点）。
- **分层：** 按 M、N 和 α∈{0.25, 0.5, 0.75} 分层，并报告 worst 和 p90。
- **checkpoint：** 只按合成验证集选择（N=100，M=5/10，每组 64 个实例，固定种子）。验证指标建议改为相对 MILP 参考解的 gap，可移植 main_v1 的 `mkp/reference.py`（HiGHS）及其缓存，因为 LP gap 偏松。不能按 Chu 结果挑选。
- **产物：** 每次正式实验保存 commit、未提交 diff、完整配置、数据 SHA、种子、checkpoint SHA 和选择规则、逐实例解向量、θ 轨迹。

## 5. 文件级改动（基于 main_v0）

**`mkp_config.py`（ModelConfig）**
- 删除：`residual_max`、`primitives`、`init_primitive*`、`kappa_*`。

  - 删除 `res_head`、`prim_head`、`kappa_head`；

  - 新增 `scalar_head`，按启用的组输出 α/γ/η。

  - 用 §3 的公式重写 `__call__`，旧的 `primitives()` 删除；

  - 支持 `theta_override`，用于实现 fixed 臂；
  - 支持 `theta_update=static`，只在 t=0 调用一次控制器；
  - trace 中记录 θ。

**`mkp_env.py`**
- 在 `lp_dual` 旁新增 `residual_lp(st, mu_prev, iters)`：
  - 只对可行且未处理的物品，按当前剩余容量求解；
  - 从上一步的 μ 热启动；

- 注意 main_v1 在 `3c7391c` 中修过的"热启动导致上界膨胀"问题：任意 μ≥0 都给出合法上界，但热启动时必须按新的残余问题重新计算 dual_value。
- `get_reward`：hard_mask 下去掉 reject 项，奖励改为 `profit/UB`。

**`mkp_Trainer.py`**
- 训练算法不改，仍为 REINFORCE + 同实例 K=16 均值基线，保证单因素可比。
- 只适配新的输出字段，并把 θ 统计写入日志。

**`Benchmark_zeroShot.py`**
- 新增 `--arm` 选项，以及 §4 的各阶段和配对输出。
- 可参考并移植 main_g1 的 `paired_comparisons()` / `paired_seed()` 和 main_v1 的 `paired_report()`，用 `git show <branch>:<path>` 取出，不要整体合并分支。
- 输出中补 α 分层、worst/p90 和 meta.json。

**`mkp_refine.py`** 不改。它只作为 `+ILS` 阶段使用，所有臂共用。

## 6. 分阶段 Codex 任务（每项都要单独回报，之后由 Claude 决定下一步）

### T0（不训练，先做）：拆解 main_v0 的 0.439% / 0.074% 从哪里来

- **研究问题：** δ_j、多采样和搜索各自贡献了多少（PP-7、L-3）。
- **做法：** 用现存的 `checkpoints/20261021_164411/best.pt` 在 Chu 180 个实例上评测以下设置：
  - (a) 原样运行；
  - (b) 推理时令 δ≡0（诊断用，不是新方法）；
  - (c) 再令 u≡0、w 取初值、δ≡0（main_v0 执行器的固定臂）；
  - 每种设置都跑 greedy / sample256 / +ILS 三个阶段。
- **验收：**
  - 产出逐实例 CSV 和分层汇总；
  - 给出 (a)−(b)、(b)−(c) 的配对差（百分点）；
  - 在报告中写明"δ 对 greedy 的贡献"，以及"固定启发式加同等搜索预算能到多少"。
- **后续决策：**
  - 如果 (c)+ILS 已经 ≤0.1%，说明 0.074% 基本来自搜索。此后主线只看 greedy，搜索阶段降为附录。
  - 如果 (b) 的 greedy 明显差于 (a)，就确认需要用 G2/G3 来替代 δ 的作用。

### T1：精简 θ（G0+G1）+ 新执行器 + 四臂对照

- **研究问题：** Q-1。在不使用 δ 的边界内，动态价格加收益指数，相对于 fixed、untrained、static 能带来多少增量。
- **改动范围：** §5 中除 G2/G3 以外的部分。
- **训练：**
  - 先跑 smoke：2 个 epoch × 20 步，检查 loss 有限、θ 统计合理、解可行。
  - 正式实验：3 个种子；`learned_dynamic` 和 `learned_static` 使用相同预算。
  - 为控制成本，建议先用 40 epochs × 250 steps。main_v0 原配置 100 epoch 约 30 小时（4090）。实际预算由 Codex 报告后再确定。
- **验收：**
  - 所有解可行且极大；
  - fixed 臂可以逐实例复现；
  - 配对报告完整；
  - 回报 greedy 的分层结果。

### T2：加入 G2（阻断基函数 + γ）

- **研究问题：** Q-4。把互斥信息作为透明基函数加入后，能否在不加入 δ 的情况下替代 δ 的作用。
- **单因素：** 只加 G2，fixed 臂同步加入 γ 的初值。
- **额外回报：** 每步耗时，以及 N=500 时的显存。

### T3：加入残余 LP（G3），按三个通路分开

- **研究问题：** Q-2、Q-6。
- **分开的三个因素：**
  - (i) 价格锚点 `root` → `residual`；
  - (ii) 加入 η·log x^LP 基函数；
  - (iii) 可选：把 LP 特征作为编码器输入。
- 每个因素单独开关。
- **额外回报：** LP 精度（在小实例上与 HiGHS LP 对照）和每步 LP 的耗时。

### T4：表示消融 + 表达能力诊断

- **表示消融（Q-5）：**
  - 可行集合作为 key 和池化集合；
  - 关键候选注意力池化；
  - 控制器去掉每步的物品 self-attention 以测成本。
- **表达能力诊断（Q-3）：**
  - 移植 main_g1 的 `mkp_diagnose.py`，即 `find_theta_witness` 和 `forced_continuation`，在新 θ 空间上做合法 θ 见证搜索。
  - 用来区分"接口表达不足"和"学习失败"，再决定是扩展基函数字典还是改训练信号（C4，例如 PPO/GAE）。
  - 找到见证只说明可达，找不到不证明不可能；冻结续行也不是 Q*。

**每一步的停止条件：**
- 如果某组加入后，`learned_dynamic` 相对 `fixed` 在 3 个种子上的配对增量不显著，就停下回报，由 Claude 决定保留还是删除该组。
- 不允许为了数字连续改动多处。

## 7. 验证方式（Codex 每项任务都要执行）

1. **静态检查：**
   - 在 `--print_config` 的输出中确认新字段；
   - θ 的总维度等于 M + 启用的标量数，并在不同 N 下打印维度，证明与 N 无关；
   - grep 确认 decoder 的分数中不再出现任何 `(B,N)` 形状的学习输出。
2. **单元级检查：**
   - fixed 臂的 greedy 结果确定且可复现；
   - 随机打乱物品顺序和资源顺序后，greedy 选出的集合不变，作为排列不变性检验；
   - `blocked_mass` 与朴素实现在小实例上逐元素一致；
   - 残余 LP 上界不低于 HiGHS LP 值，原始解近似一致。
3. **smoke 训练：** 2 epoch，loss 有限，θ 统计与梯度范数正常，无非有限梯度。
4. **基准：** 在 Chu 180 个实例（M∈{5,10}）上跑所有臂和所有阶段，所有解通过 `is_feasible`。阶段与预算按 §4 写入 summary 和 meta.json。
5. **回报：** 修改清单、命令、配置、产物路径、commit 与 diff、未验证的假设和偏离。不能用"实现完成"代替"效果已验证"。

## 8. 明确不做的事

- 不合并 main_v1 / main_g1 分支，只按需移植评测和诊断工具。
- 不在 T1–T3 中更换训练算法，不引入 PPO/GAE、critic 或续行排序。
- 不把 Chu 结果用于 checkpoint 选择或调参。
- 不把任何多采样或搜索阶段的数字写成"主方法 gap"。
