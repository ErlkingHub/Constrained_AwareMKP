## 2. 必须保留的主研究边界

研究总题目是“面向组合优化问题的结构感知和策略学习”，MKP 是第一个载体。核心链路为：

> 当前残余问题 → 学习控制器 → 低维、可解释的状态级 θ → 无可训练参数的透明执行规则 → 可行解。

| 边界                       | 接手后的具体要求                                                                                                                          |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 学习与执行解耦（P-1）      | 学习负责资源价值判断与评分准则控制；固定规则负责逐步执行和可行性。                                                                        |
| 接口与物品数 N 无关（I-1） | θ 的维度不随 N 增长；可以依赖资源数 M，但须说明复杂度，警惕 O(M²) 膨胀。                                                                  |
| 无逐物品学习输出（I-2）    | 主方法不输出逐物品可学习残差、logits 或 Q 值。执行器可以用 θ 与固定透明特征计算物品分数；编码器内部的物品表示不等于被禁止的逐物品动作头。 |
| 语义与动态性（I-3、I-4）   | 明确 θ 每个分量的含义，并在每步或明确定义的决策点按残余状态更新。动态是否优于静态需要实验验证。                                           |
| 可行性由规则保证（I-5）    | 可使用可行性 mask，也可使用“感知 + 拒绝”；纲领未限定唯一方式。最终解必须满足容量约束。                                                    |
| 可训练（I-6）              | 明确 θ 到动作分布的梯度路径或替代训练方式，不能用黑盒超参数搜索代替策略学习。                                                             |
| 单独测量学习增量（P-3）    | 在同一执行器、相同推理预算下保留固定 θ、学习静态 θ、未训练 θ、学习动态 θ 的对照。各臂的精确定义由实验设计写清。                           |
| 分阶段、匹配预算（P-4）    | 单轨迹 greedy、best-of-K 采样、搜索 / 修复分别报告，记录各阶段时间与预算。                                                                |

主方法不能悄悄加入逐物品学习修正、搜索、修复、beam search 或求解器选取整数解，并继续沿用原方法名称与贡献解释。如需研究扩展机制，由 Claude 明确其问题和作用，作为单独命名的实验臂；涉及纲领改变时交由用户决定。合法 θ 见证搜索是表达能力诊断，不应混入主方法的推理成绩。

LP 松弛、对偶价格与上界可以作为运筹先验、固定评分信息或训练信号；它们不等同于直接调用求解器替代策略完成整数选物。

## 7. 实验与证据纪律

沿用主文档的 A～E 等级：A 为源码或原始结果直接确认；B 为已实现但缺少受控对照；C 为假设；D 为原始材料缺失或不可复算的历史探索；E 为计划。实现事实达到 A，不代表其性能增益也达到 A。

- 训练、验证、最终测试分开。checkpoint 按合成验证集选择，不能按 Chu 测试 gap 挑选；反复用于开发反馈的基准不能同时被当作完全独立的最终测试。
- 学习增益采用独立训练种子与独立实例，按实例配对；同一实例的多条轨迹或多个前缀不是独立实例证据。
- `best-known gap = 100 × (best_known − objective) / best_known`，保留符号，以逐实例 gap 汇总；gap 差值用百分点。best-known 不是最优性证书，LP 上界 gap 与 best-known gap 不能互换。
- 同执行器、同阶段、匹配预算比较；报告整体与 N / M / 容量比分层结果、尾部、可行性和时间，说明 LP、采样和搜索的计时边界。
- 每次正式实验保存问题、commit、未提交补丁、完整有效配置、数据 SHA、训练 / 验证 / 评估种子、实际预算、checkpoint SHA 与选择规则、硬件 / 软件环境、逐实例结果与解序列。
- 区分表达能力、训练是否学会、基准表现三件事。不得将合法 θ 见证称为全局最优性证明，将冻结策略续行称为精确 Q*，或将一次 smoke 检查称为正式效果验证。
